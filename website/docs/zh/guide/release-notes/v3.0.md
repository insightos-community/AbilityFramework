# v3.0 发布说明

AbilityFramework 3.0 是一次重大架构升级，引入了能力实例化机制、Skill 文档系统、统一日志层、Zenoh 远程执行等多项核心改进。

## 核心新功能

### 能力实例化

引入 CR 模板与 Instance 运行时实例分离机制。实例拥有独立 `instance_id` 和冻结的 `spec_snapshot`，支持同一能力的并发实例、单例约束和 autoStart 自动拉起。

详见：[能力实例](/guide/release-highlights/instance)

### Skill 文档系统

能力包可携带面向 AI Agent 的技能说明文档（`skills/` 目录），框架在安装时镜像到固定位置，通过 HTTP API 暴露给 WebUI、MCP Server 和上层业务集成方。

详见：[Skill 文档系统](/guide/release-highlights/skill)

### 统一日志层

引入 `ILogger` 接口 + 策略模式，统一封装 glog 和 insightos-log 两种后端，支持 fmt 风格宏、流式兼容宏和 CHECK 断言，并集成 HTTP 链路追踪。

详见：[日志系统](/guide/release-highlights/log)

### Zenoh 远程执行

支持通过 zenoh 协议远程启动能力进程，适用于无本地 package 目录的节点。

详见：[Zenoh 远程执行](/guide/release-highlights/zenoh)

## 架构改进

### CRD 内置化与 Manifest 引入

将 CRD 从能力包中抽离为框架内置定义，原 CRD 中的能力特有字段迁移到 `ability.manifest.yaml`。验证流程改为两级（框架级 + 能力级）。

详见：[架构演进设计](/guide/release-highlights/architecture-evolution)

### Service CRD（实验性）

新增 Service 类型资源，支持常驻运行、重启策略（always/on-failure/never）和健康检查探活。

### Service CR 管理

新增 `/api/service-cr` 系列 endpoint，支持 Service 类型 CR 的运行时增删查。

## API 变更

- 新增 `/api/instance` 系列接口（替代旧的直接操作 CR 的方式）
- 新增 `/api/skill` 系列 Skill 文档接口
- 新增 `/api/service-cr` 系列 Service CR 接口
- 新增 `/api/manifest` 能力清单接口
- 废弃 `POST/DELETE /api/cr`（410 Gone），CR 由包/YAML 决定
- 新增 `/api/internal/test-message`、`/api/internal/test-download-package` 测试端点

完整 API 列表见 [HTTP API 参考](/api/http-api)。
