# v3.0 release notes

AbilityFramework 3.0 is a major architectural upgrade, introducing core improvements such as the ability instantiation mechanism, the Skill document system, a unified logging layer, and Zenoh remote execution.

## Core new features

### Ability instantiation

Introduces the separation of CR templates and runtime Instances. Instances have their own `instance_id` and a frozen `spec_snapshot`, supporting concurrent instances of the same ability, singleton constraints, and autoStart auto-launch.

See: [Ability instances](/en/guide/release-highlights/instance)

### Skill document system

Ability packages can carry AI-Agent-facing skill documents (the `skills/` directory); the framework mirrors them to a fixed location at install time and exposes them via HTTP API to the WebUI, MCP Server, and upper-layer integrators.

See: [Skill document system](/en/guide/release-highlights/skill)

### Unified logging layer

Introduces the `ILogger` interface + strategy pattern to uniformly wrap the glog and insightos-log backends, supporting fmt-style macros, streaming-compatible macros, and CHECK assertions, with integrated HTTP tracing.

See: [Logging system](/en/guide/release-highlights/log)

### Zenoh remote execution

Supports launching ability processes remotely via the zenoh protocol, suitable for nodes without a local package directory.

See: [Zenoh remote execution](/en/guide/release-highlights/zenoh)

## Architectural improvements

### CRD internalization and the introduction of the Manifest

Extracts the CRD from ability packages into a framework-built-in definition; the ability-specific fields of the original CRD are migrated to `ability.manifest.yaml`. The validation flow becomes two-level (framework-level + ability-level).

See: [Architecture evolution design](/en/guide/release-highlights/architecture-evolution)

### Service CRD (experimental)

Adds the Service resource type, supporting long-running execution, restart policies (always/on-failure/never), and health-check probing.

### Service CR management

Adds the `/api/service-cr` family of endpoints, supporting runtime add/delete/query of Service-type CRs.

## API changes

 Added the `/api/instance` family of endpoints (replacing the old direct CR manipulation)
- Added the `/api/skill` family of Skill document endpoints
- Added the `/api/service-cr` family of Service CR endpoints
- Added the `/api/manifest` ability manifest endpoint
- Deprecated `POST/DELETE /api/cr` (410 Gone); CRs are determined by packages/YAML
- Added the `/api/internal/test-message`, `/api/internal/test-download-package` test endpoints

For the full API list, see the [HTTP API reference](/en/api/http-api).
